# Capture-First Replacement Transport

## Status

Mission 4 adds the first replacement-service transport layer.

It is intentionally **capture-first**. It does not contain a reconstructed NBA 2K17 login response and it does not claim any unverified route, header, field ID, or body schema is authentic.

## Layout

```
server/
  config.example.json
  src/
    index.js
    capture/
      sanitize.js
      capture-store.js
    response/
      profiles.js
    transport/
      http-capture.js
      https-server.js
```

## Default behavior

The default response profile is:

`CAPTURE_ONLY_404`

A request is:

1. accepted through the configured HTTPS listener,
2. read with a strict body-size limit,
3. preserved byte-for-byte in a gitignored raw-local directory,
4. hashed with SHA-256,
5. described in raw metadata,
6. optionally exported into a sanitized metadata fixture,
7. answered with an explicitly test-only response profile.

No guessed NBA 2K17 protocol response is generated by default.

## Raw-local evidence

Default:

`server/captures/raw-local/`

A successful capture writes:

```
<capture-id>.body.bin
<capture-id>.request.json
```

The body file is exact bytes received by the server.

The raw metadata can include request headers and local paths, so the entire raw-local directory is gitignored.

## Sanitized evidence

Sanitized exports contain:

- capture ID,
- UTC timestamp,
- method,
- path,
- redacted query indicator,
- HTTP version,
- host,
- redacted headers,
- content type,
- body byte length,
- body SHA-256,
- VCFIELDLIST_SIZE if present,
- TLS protocol/cipher/ALPN/SNI metadata,
- response-profile metadata.

They do **not** contain the raw request body.

Sensitive headers such as authorization, cookies, session/token headers, Steam-ticket/Steam-ID headers, and API-key-like headers are replaced with `[REDACTED]`.

Query strings are not copied into sanitized records.

## Response profiles

Current profiles are experiment controls only:

- `CAPTURE_ONLY_404`
- `TEST_ONLY_EMPTY_200`
- `TEST_ONLY_EMPTY_BINARY_FIELD_LIST`

The final profile exists solely to exercise the cross-version reference framing and is labeled:

`CROSS_VERSION_REFERENCE_TEST_ONLY`

It must not be presented as an NBA 2K17 response.

## TLS

The HTTPS server accepts either:

- a PFX path (+ optional passphrase file), or
- certificate + private-key paths.

Certificate/key material stays outside the repository.

TLS minimum/maximum versions and cipher selection are configurable. The example values are operational defaults only and are **not NBA 2K17 protocol evidence**.

A `secureConnection` event is logged as transport-level establishment only. It does not prove application-level certificate acceptance or the absence of certificate pinning.

Likewise, a TLS FIN/EOF/error after certificate delivery does not establish pinning. The exact state/error is evidence; the cause remains unknown unless separately proven.

## Body limits

The default request-body cap is 1 MiB.

A body exceeding the configured limit receives an empty HTTP 413 response and is not committed as a normal capture.

This prevents malformed or unexpected traffic from consuming unbounded memory.

## `VCFIELDLIST_SIZE`

If the incoming request contains a `VCFIELDLIST_SIZE` header, its non-negative integer value is recorded.

The server does not require the header and does not infer field-list framing merely because the header exists.

## Running

Copy the example configuration to a local, ignored location and point it at developer-owned TLS material.

Example:

```
node server/src/index.js C:\path\to\local-config.json
```

Do not place private certificate material in the repository.

## Mission 4 evidence boundary

This layer establishes only that the project can:

- terminate developer-controlled HTTPS,
- preserve application requests,
- segregate raw and sanitized evidence,
- select deterministic test-only responses,
- reject oversized bodies,
- record TLS/HTTP metadata.

It establishes **nothing new about the NBA 2K17 wire protocol** until a future authorized client capture reaches it.
