# Internal Domain Contracts v0

These contracts describe **our replacement platform's internal data**, not the original game's wire protocol. No field name below should be treated as evidence that an equivalent 2K17 field exists.

## Design goals

- Stable IDs owned by us.
- Raw protocol fields stay at the adapter boundary.
- Public profiles never require exposing raw platform account identifiers.
- Version every persisted shape.
- Preserve unknown data instead of silently assigning meanings.
- Make later Player Passport, Crews, match history, rankings, and telemetry additive.

## PlayerIdentity v0

```json
{
  "schema_version": 0,
  "player_id": "plr_...",
  "platform": "steam",
  "platform_subject": "private-server-side-stable-subject",
  "display_name": "Mgtda",
  "created_at": "2026-10-05T00:00:00Z",
  "last_seen_at": "2026-10-05T00:00:00Z",
  "status": "active"
}
```

### Rules

- `player_id` is generated by our service and is the canonical key elsewhere.
- `platform_subject` is server-private. Public APIs should expose `player_id`, not the raw source identifier.
- Display names are mutable and must not be used as identity keys.

## Session v0

```json
{
  "schema_version": 0,
  "session_id": "ses_...",
  "player_id": "plr_...",
  "started_at": "2026-10-05T00:00:00Z",
  "last_seen_at": "2026-10-05T00:02:00Z",
  "ended_at": null,
  "status": "active",
  "client": {
    "title": "nba2k17-pc",
    "version_observed": null
  },
  "environment": "replacement"
}
```

### Rules

- One player may have many historical sessions.
- A session must never be inferred solely from display name.
- Keep-alive traffic updates `last_seen_at`; it does not create a new player.
- Re-login may rotate `session_id` while preserving `player_id`.

## EndpointObservation v0

This is the bridge between clean-room evidence and implementation.

```json
{
  "schema_version": 0,
  "observation_id": "obs_...",
  "captured_at": "2026-10-05T00:00:00Z",
  "player_id": "plr_...",
  "session_id": "ses_...",
  "route": "/nba/2k17/example",
  "method": "POST",
  "request_bytes": 0,
  "response_bytes": 0,
  "handler": "ExampleHandler",
  "response_class": "intentional",
  "evidence_class": "OBSERVED",
  "fixture_ref": "sanitized-fixtures/...",
  "notes": null
}
```

Allowed `response_class`:

- `intentional`
- `reference-derived`
- `generic-fallback`
- `error`

Allowed `evidence_class`:

- `OBSERVED`
- `DERIVED`
- `REFERENCE`
- `HYPOTHESIS`
- `IMPLEMENTED`

## Match v0

Do not wire this into the live server until a real match-completion boundary is observed.

```json
{
  "schema_version": 0,
  "match_id": "mtch_...",
  "mode": "unknown",
  "started_at": null,
  "ended_at": null,
  "status": "observed",
  "teams": [],
  "participants": [],
  "source": {
    "evidence_class": "OBSERVED",
    "fixture_refs": []
  }
}
```

A participant eventually takes this shape:

```json
{
  "player_id": "plr_...",
  "team_id": "team_...",
  "result": "win",
  "stats": {
    "points": null,
    "rebounds": null,
    "assists": null,
    "steals": null,
    "blocks": null,
    "turnovers": null,
    "field_goals_made": null,
    "field_goals_attempted": null,
    "three_points_made": null,
    "three_points_attempted": null,
    "free_throws_made": null,
    "free_throws_attempted": null,
    "teammate_grade": null
  }
}
```

Null means **unknown/not captured**, never zero.

## Persistence rule

Protocol adapters may retain sanitized unknown fields for research, but product tables should only receive fields whose semantics are sufficiently established.

**Unknown is a valid state. A guessed value is not.**
